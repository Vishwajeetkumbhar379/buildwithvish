Every Monday someone opens three ad managers, scrolls through columns and tries to remember which numbers were different last week. Ad Performance Copilot is a small command-line tool that does that first pass. You give it one CSV file with your Meta, Google and LinkedIn results, plus your target cost per acquisition, and it returns a review: totals, platform and campaign tables, a list of problems worth acting on and a suggested budget shift. This page explains what each check does, how to run it on the sample data in about 10 minutes, and where its simple rules will mislead you.

In short
  • You export your ad results to one CSV. The tool never connects to an ad account.
  • It calculates the same metrics for every platform and applies five fixed rules: creative fatigue, wasted spend, inefficient campaigns, scale candidates and sudden cost spikes.
  • It proposes a budget shift that keeps total spend flat. Optionally, Claude writes a short client summary from the report.
  • The sample account is fictional. Version 0.1.0, four tests, rules you can read in one file.

The problem, and who it's for

Paid media reviews usually go wrong in one of two ways. Either nobody has time to do them, or the review is done by eye, so the same campaign gets a pass one week and a telling-off the next. I wanted the decision rules written down, so the review takes minutes and the reasoning is the same every week.

It's for in-house marketers and small agencies running paid social and search who can run a command in a terminal. If you can't, the last section gives you a chat version of the same review.

What it does, step by step

  1. Load your CSV. One row per day, platform, campaign and creative, with spend, impressions, reach, clicks, conversions and revenue.
  2. Calculate the basics. Click-through rate, cost per click, cost per 1,000 impressions (CPM), conversion rate, cost per acquisition (CPA), return on ad spend (ROAS) and frequency, all worked out the same way for every platform.
  3. Check creative fatigue. For each creative it compares its first week with its last week. If click-through rate fell by more than 25% while frequency rose by more than 30%, it flags fatigue and suggests rotating in new creatives with the same hook.
  4. Check wasted spend. A campaign that spent more than twice your target CPA with zero conversions gets an "Act" flag: pause it, check tracking and the landing page.
  5. Check inefficient campaigns. CPA above 1.5 times your target is flagged too.
  6. Spot scale candidates. CPA under 70% of target and ROAS at or above target gets a "Watch" flag with a gentle suggestion: scale by 15 to 20% and watch for three to four days.
  7. Spot sudden spikes. It compares the last three days with the seven days before, and flags a CPA rise of 40% or more.
  8. Propose a budget shift. Weak campaigns give up to 20% of their spend. That money goes to campaigns with CPA under 80% of target, weighted towards the most efficient. Total spend stays the same.
  9. Write the report. The output is a Markdown file. With --ai, Claude adds a 4 to 5 sentence summary, written from the report's numbers.

There are no required dependencies, only Python 3.11 or newer. The Claude summary needs the optional anthropic package and an API key.

How to run it

The repo is github.com/Vishwajeetkumbhar379/ad-performance-copilot. From the README:

  1. Clone it and go into the folder.
  2. Install it: pip install -e ".[dev]"
  3. Run it on the sample: adcopilot data/ads_export.csv --target-cpa 40 --target-roas 1.5
  4. Run the tests: pytest
  5. For the summary, install pip install -e ".[ai]", set ANTHROPIC_API_KEY and add --ai to the command.

--target-cpa is required, and --target-roas defaults to 2.0. The report is saved to reports/weekly_review.md unless you pass --out, so give your own files a different output name and keep the sample intact.

Using your own data

Your CSV needs exactly these columns: date, platform, campaign, creative, spend, impressions, reach, clicks, conversions, revenue. Meta, Google and LinkedIn export under different names, so rename the headers once and keep the result as a template. Use dates like 2026-09-01 (year, month, day), because the code sorts them as text. A missing column makes the run fail.

Privacy

Ad exports are business data, and some clients treat them as confidential. Check you're allowed to use the figures, and think twice before sending a client's numbers to an AI service with --ai.

What it can't do

  • It can't tell you why. It flags a campaign with a high CPA. Whether the cause is the audience, the offer, tracking or a bad week is your call.
  • The rules are mine, and they're blunt. The thresholds (25%, 1.5 times, 40%) are sensible starting points that I haven't validated against anyone's account. Change them in analysis.py to suit your market.
  • The budget shift is rough. It picks recipients on CPA alone, without the ROAS check that the scale flag uses, so it can send money to a campaign that is cheap per conversion but earns little revenue. It also ignores platform learning phases, daily caps and how much more an audience can absorb. Treat it as a first draft for a human decision.
  • Frequency is approximate. The tool adds up the daily reach figures, but reach is not additive across days on real platforms, so the number is only a trend signal.
  • Currency and attribution are fixed. Reports are labelled in euros, and it takes the conversion and revenue figures you give it, so platform double-counting and attribution disagreements pass straight through.
  • It doesn't connect to your ad accounts. You export the CSV by hand.
  • The AI summary can slip. The prompt asks Claude to use only the report's numbers, which is an instruction, not a guarantee. Read the summary against the tables before it goes to a client.

What building it taught me

  • Put the decision rules in writing. When an "Act" flag has a stated threshold, you can argue with the threshold. A feeling is harder to argue with.
  • Let code do the arithmetic and AI do the wording. Claude only sees the finished report. It never calculates a metric, which keeps the numbers checkable.
  • Separate "Act" from "Watch". A short list of things to do today, and a second list of things to keep an eye on, makes a review easier to use than a long list of everything.
  • A fictional account is a good test. The sample data is built with known problems, and a test checks that the tool finds them. It tells you the rules work on a story, not that they work on your account.

Build a simple version without code

For the same thinking without a terminal, paste a week of results into a chat and use this prompt. The guides A weekly report that writes itself and 20 prompts I use every week for marketing show how to turn it into a routine, and Campaign Report Autopilot covers the reporting side.

Here is last week's ad data by campaign: [paste spend, results, CPA, frequency]. My target CPA is [number] and my target ROAS is [number]. Flag campaigns with a CPA more than 1.5 times target, frequency above 3, or a CPA rising for three days in a row. Suggest a budget shift that keeps total spend the same, and explain each move in one line. If a campaign has too little data to judge, say so instead of guessing.

Then ask for a version your client can read:

Using only the numbers in the review above, write a summary for my client in 4 to 5 sentences: the biggest win, the biggest problem and what changes next week. Do not add any figures I have not given you. Plain language, no jargon, no bullet points.

Check the figures yourself before you send anything. AI is good at wording and unreliable at arithmetic across a long table.
